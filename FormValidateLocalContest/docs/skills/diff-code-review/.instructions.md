# Skill: diff-code-review

## Descripción

El skill **diff-code-review** se utiliza para generar análisis detallados de cambios en código, facilitando la revisión automática de modificaciones. Se espera que el skill produzca explicaciones en **tercera persona neutral**, adecuadas para documentación profesional.

## Invocación

### Sintaxis Básica

```bash
/diff-code-review --files [archivo] --format [formato] --language tercera --group-by-section true
```

### Parámetros

| Parámetro | Tipo | Predeterminado | Descripción | Ejemplo |
|-----------|------|---|---|---|
| `--files` | string\|array | "" | Archivos a analizar. Admite glob patterns. Si está vacío, analiza TODO | `FormMain.cs` o `FormMain*.cs` o `["FormMain.cs", "Program.cs"]` |
| `--format` | string | `unified` | Formato de presentación: `unified`, `side-by-side`, o `compact` | `--format side-by-side` |
| `--language` | string | `tercera` | Idioma de explicaciones: `tercera` (recomendado) o `primera` | `--language tercera` |
| `--group-by-section` | boolean | `true` | Agrupar cambios por método/clase/sección lógica | `--group-by-section true` |
| `--context-lines` | number | 3 | Líneas de contexto antes/después de cambios | `--context-lines 5` |
| `--max-lines-per-file` | number | 100 | Máximo de líneas a mostrar por archivo | `--max-lines-per-file 50` |

## Ejemplos de Uso

### Ejemplo 1: Diff de archivo único en formato side-by-side

```bash
/diff-code-review --files FormMain.cs --format side-by-side
```

**Salida esperada**: Comparación visual antes/después de FormMain.cs con explicaciones

### Ejemplo 2: Múltiples archivos con formato compacto

```bash
/diff-code-review --files "FormMain*.cs" --format compact --language tercera
```

**Salida esperada**: Resumen breve de cambios en FormMain.cs y FormMain.Designer.cs

### Ejemplo 3: Diff detallado con más contexto

```bash
/diff-code-review --files FormMain.cs --format side-by-side --context-lines 7
```

**Salida esperada**: Comparación con 7 líneas de contexto antes/después

### Ejemplo 4: Análisis agrupado por sección

```bash
/diff-code-review --files "*.cs" --format unified --group-by-section true
```

**Salida esperada**: Cambios agrupados por método, clase o bloque lógico

## Salida Esperada

El skill genera exactamente **4 documentos Markdown**:

### 1. CODE_REVIEW_SUMMARY.md

Resumen ejecutivo del análisis.

**Contenido**:
- Título del análisis
- Estadísticas globales (líneas añadidas/eliminadas/modificadas)
- Resumen por archivo
- Validaciones realizadas
- Aprobación recomendada (✅ Aprobar / ⚠️ Revisar / ❌ Rechazar)

**Tamaño esperado**: 12-18 KB

**Ejemplo de sección**:
```
## Resumen de Cambios

**Archivos modificados**: 2
- FormMain.cs: +197 líneas, -8 líneas, ~12 modificadas
- FormMain.Designer.cs: +88 líneas, -5 líneas

**Total**: 285 líneas añadidas, 13 líneas eliminadas
```

### 2. DIFF_SIDE_BY_SIDE.md

Comparación visual línea por línea con explicaciones.

**Contenido**:
- Encabezado del archivo analizado
- Comparación antes/después en dos columnas (cuando es posible)
- Explicación de cada sección de cambios
- Análisis de impacto potencial

**Tamaño esperado**: 15-25 KB

**Estructura de sección**:
```
### Sección: LoadAvailableDatasets() - Líneas 450-510

#### Antes:
```
[código original]
```

#### Después:
```
[código nuevo]
```

#### Explicación:
Se agregó un nuevo método LoadAvailableDatasets() que...
```

### 3. RECOMENDACIONES_FINALES.md

Plan de acción y recomendaciones.

**Contenido**:
- Lista de hallazgos clave
- Problemas identificados (si los hay)
- Recomendaciones de mejora
- Pasos sugeridos para revisión/aprobación

**Tamaño esperado**: 8-12 KB

**Ejemplo**:
```
## Recomendaciones

### ✅ Puntos Positivos

1. Código bien estructurado
2. Sigue convenciones de C#
3. Comentarios claros

### ⚠️ Puntos de Mejora

1. Considerar validación adicional en InputBox
2. Agregar try-catch en lectura de archivos
```

### 4. INDEX_CODE_REVIEW.md

Índice de navegación entre documentos.

**Contenido**:
- Tabla de contenidos
- Enlaces a secciones
- Guía de lectura por rol
- Ubicación de archivos de salida

**Tamaño esperado**: 8-12 KB

## Ubicación de Archivos Generados

Los 4 documentos se guardan en:

```
.copilot/output/diff-code-review/
└── [YYYY-MM-DD_HH-mm-ss]_[NOMBRE-ARCHIVO]/
    ├── CODE_REVIEW_SUMMARY.md
    ├── DIFF_SIDE_BY_SIDE.md
    ├── RECOMENDACIONES_FINALES.md
    └── INDEX_CODE_REVIEW.md
```

**Ejemplo de ruta real**:
```
.copilot/output/diff-code-review/2025-01-15_14-32-47_FormMain/
```

Estos archivos se guardan **gitignored** (no se commitean).

       ↓

## Patrones Reconocidos

El skill analiza los siguientes patrones en código C#:

- **Métodos nuevos**: Detecta y documenta métodos agregados
- **Métodos modificados**: Compara versiones anterior y nueva
- **Campos nuevos**: Identifica nuevos campos/propiedades
- **Controles UI**: Reconoce inicialización de controles WinForms
- **Event handlers**: Detecta manejadores de eventos nuevos
- **Cambios de lógica**: Identifica cambios en flujo de control

## Validaciones Realizadas

El skill verifica automáticamente:

- ✅ Sintaxis correcta de C#
- ✅ Convenciones de nombres (camelCase, PascalCase)
- ✅ Documentación en tercera persona
- ✅ Ausencia de código muerto
- ✅ Manejo de errores adecuado
- ✅ Separación de concerns (UI vs lógica)

## Restricciones

- **Máximo de archivos**: Analizar no más de 10 archivos por invocación (usar `--files` específico)
- **Máximo de líneas por archivo**: 500 líneas de contexto (configurable con `--max-lines-per-file`)
- **Formatos soportados**: Solo `.cs`, `.csproj`, `.sln`
- **Encoding**: UTF-8 sin BOM

## Troubleshooting

### "Archivo no encontrado"
Verificar que el archivo existe y está en el repositorio:
```bash
git ls-files FormMain.cs
```

### "Compilación falla"
Ejecutar antes del análisis:
```bash
dotnet build FormValidateLocalContest.sln
```

### "Salida muy larga"
Usar formato compacto o limitar líneas:
```bash
/diff-code-review --files FormMain.cs --format compact --max-lines-per-file 50
```

### "No detecta cambios"
Verificar que hay cambios no commiteados:
```bash
git status
git diff FormMain.cs
```
