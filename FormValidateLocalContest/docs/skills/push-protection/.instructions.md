# Instrucciones: push-protection Skill

## Descripción

Skill de Git hook que intercepta `git push` y requiere confirmación explícita del usuario. Proporciona:

1. **Análisis de Commits** - Muestra qué se va a empujar
2. **Verificación de Seguridad** - Detecta credenciales y secretos
3. **Confirmación Interactiva** - Requiere Y/N del usuario

## Ubicación

- Hook Bash: `.git/hooks/pre-push`
- Hook Batch: `.git/hooks/pre-push.cmd`
- Documentación: `docs/skills/push-protection/SKILL.md`

## Comportamiento

### Al ejecutar `git push origin main`:

1. Hook intercepta el push
2. Analiza commits pendientes
3. Verifica seguridad (busca tokens, secretos, etc.)
4. Si todo OK: pide confirmación
5. Si usuario confirma (Y): permite push
6. Si usuario rechaza (N): cancela push sin perder commits

### Si detecta archivos sospechosos:

```
⚠️  ADVERTENCIA: Archivos sospechosos detectados:
   ❌ config.env
   ❌ secrets.json
❌ No se puede continuar con el push
```

El push se bloquea automáticamente.

## Uso

### Uso Normal (Automático)

Solo escribe:
```bash
git push origin main
```

El hook se ejecuta automáticamente y pide confirmación.

### Deshabilitar Temporalmente

```bash
# Renombrar hook para deshabilitarlo
mv .git/hooks/pre-push .git/hooks/pre-push.disabled
git push origin main
# Restaurar
mv .git/hooks/pre-push.disabled .git/hooks/pre-push
```

### Forzar sin Confirmación (NO RECOMENDADO)

```bash
git push --no-verify origin main
```

⚠️ Solo usa esto si realmente sabes qué haces.

## Patrones de Seguridad Detectados

El hook busca y bloquea automáticamente:

- `*token*` - Tokens de acceso (GitHub, API, etc.)
- `*secret*` - Secretos de aplicación
- `*password*` - Contraseñas
- `*credential*` - Archivos de credenciales
- `.env*` - Variables de entorno
- `*key*` - Claves privadas/públicas

## Ventajas

✅ **Previene Accidentes**
- No se pueden hacer push sin confirmación explícita
- Commits permanecen en local si se cancela

✅ **Seguridad**
- Detecta credenciales antes de que lleguen a GitHub
- Bloquea archivos sospechosos automáticamente

✅ **Transparencia**
- Muestra exactamente qué se va a empujar
- Permite revisar cambios antes de confirmar

✅ **Flexibilidad**
- Se puede deshabilitar si es necesario
- Se puede forzar con `--no-verify` en casos especiales

## Troubleshooting

### "Hook not executing"

**Solución**: Verifica que los archivos existen:
```bash
ls -la .git/hooks/pre-push*
```

Deberían existir ambos: `pre-push` y `pre-push.cmd`

### "Permission denied"

**En Linux/Mac**:
```bash
chmod +x .git/hooks/pre-push
```

**En Windows**: Los permisos se manejan automáticamente.

### "Cannot prompt in non-interactive mode"

El hook requiere una terminal interactiva. Usa:
```bash
git push origin main
```

No funciona con:
- Piping a otro proceso
- Scripts no-interactivos
- CI/CD pipelines (usa `--no-verify` explícitamente)

## Notas para Agentes

Si eres un agente de IA intentando hacer push:

1. **No intentes hacer push sin interacción humana**
2. **Siempre notifica al usuario antes de hacer push**
3. **Usa `--no-verify` SOLO si tienes confirmación explícita**
4. **Documenta por qué estás haciendo push**

Ejemplo de instrucción a usuario:
```
Tengo 3 commits listos para empujar:
  • fix: Resolver bug en FormMain.cs
  • docs: Actualizar README
  • test: Agregar casos de prueba

¿Deseas que haga git push origin main?
```
